# Phase 7: direction change and reverse driving

**Status:** started 2026-11-18. Needs phase 2 (launch layer); car checks wait for phase 5's
car access.

**Goal:** a route through lanelets tagged `direction_change=yes` (a three-point turn) drives
end to end: forward, stop at the cusp, reverse, stop, forward. First in Autoware's planning
simulator, then in the RC simulator through our real vehicle interface, then on a car.

## What upstream gives

`autoware_behavior_path_direction_change_module` (2.1.0 only). Switched by
`launch_direction_change_module` (default false), read by `behavior_planning.launch.xml` from
the module preset. Parameters: `autoware_planning_config/.../autoware_behavior_path_direction_change_module/direction_change.param.yaml`.

- Activates only on route lanelets whose **lanelet** carries `direction_change=yes`
  (`lanelet.attributeOr("direction_change", "none") == "yes"`).
- A cusp is a yaw jump above `cusp_detection_angle_threshold_deg` (90) between consecutive
  points of the route centerline through the tagged lanelets.
- Reverse legs get `longitudinal_velocity_mps = -|v|` and yaw + pi; the module zeroes the
  velocity at each cusp and waits `th_stopped_time` below `stop_velocity_threshold`
  (1.0 m/s stock: far too high for a 1 m/s car, AutoSDV lowers it).
- No gear handling in the module: Autoware's shift decider turns the trajectory's sign into
  `/control/command/gear_cmd`, and the longitudinal controller waits until
  `/vehicle/status/gear_status` matches before it drives.
- Upstream ships no example map and no tests.

## What AutoSDV lacks

The vehicle interface never drives backward, on purpose (`longitudinal.py`, "The shell does
not drive backward on purpose"):

1. a negative target only brakes; nothing performs the ESC's arming sequence
   (`docs/design/esc-pwm-model.md`: pull to `reverse_arm_pwm` or lower, return to
   `ARM_RETURN`, then at or below `reverse_start_pwm`);
2. the KY-003 hall sensor gives speed without direction, so `/vehicle/status/velocity_status`
   is never negative;
3. the gear manager infers the gear from PWM and velocity, not from the ESC state.

Steering is open loop (tire angle to servo PWM), so reversing does not change its sign.

**Reverse stays off unless asked for.** Autoware's start and goal planners can also emit
reverse segments; today the car brakes there. A course car running `develop` must keep doing
exactly that, so reverse driving is an actuator parameter, `reverse_enabled`, default
**false**, which only `use_direction_change_module:=true` (or an explicit override) turns on.
